# 단일 펄린 노이즈 스테이지 생성기 구현 계획

작성: 2026-09-27. 상태: 기본 생성기 구현. [생성기 논의](2026-09-25-stage-generator-discussion.md)의 노이즈 기반 방향을 첫 단계로 구체화한다.

## 1. 이번 단계의 동작 계약

- 생성 범위의 출처는 씬의 `WorldBounds2D`다. 기존 1×1 직사각 `Grid`에서 월드 경계 내부와 면적이 겹치는 셀을 먼저 구하고, 그 영역을 상하좌우로 각각 한 셀씩 넓힌다. `WorldBounds2D` 자체는 바꾸지 않는다.
- 지형 판정은 단일 `Mathf.PerlinNoise` 호출과 임계값 비교만 사용한다. `noise < density`면 `MiningTileDefinition` 1종을 배치하고, 그렇지 않으면 빈 셀로 둔다. `density`가 커질수록 암반 점유율이 대체로 높아진다. 이것은 목표 점유율의 정확한 보장은 아니다.
- 가로·세로 노이즈 스케일은 각각 **셀 단위로 패턴이 반복되는 대략적인 길이**이며, 양수다. 샘플 좌표는 `((x + 0.5) / horizontalScale + offsetX, (y + 0.5) / verticalScale + offsetY)`로 정의한다. 값이 커지면 해당 축의 지형 덩어리가 길어진다.
- `seed`는 오프셋 쌍을 결정한다. 고정 시드로 재생성하면 같은 셀 배열이 나온다. 일반 입장에서는 새 시드를 사용하고 실행 로그에 사용 시드를 남긴다. 생성기 전용 난수를 써서 생물 배치 난수와 분리한다.
- 생성 결과의 플레이어 시작 위치, 연결성, 귀환 가능성은 검사하거나 고치지 않는다. 시작 위치 제외/해당 타일 제거는 후속 단계다.
- 외곽 강제 암반, 방·통로 굴착, 평활화, 광맥, 복수 노이즈, 도달성 보정은 이번 단계에 넣지 않는다.

## 2. 좌표와 경계

`WorldBounds2D.WorldMin/WorldMax`를 읽고 `StageMap.Grid`의 셀 좌표로 바꾼다. 현재 씬의 Grid/Tilemap은 원점, 단위 스케일, 회전 0, 직사각 셀 1×1이다. 이 전제가 깨지면 경계를 잘못 채우지 않도록 생성 전 오류로 중단한다. `WorldBounds2D`도 회전된 경계는 `WorldMin/WorldMax` 구현이 실제 네 꼭짓점의 AABB가 아니므로 이 버전에서는 회전 0을 요구한다. 이동/확대·축 반전이 필요한 경우 변환된 네 꼭짓점을 계산하는 후속 변경으로 분리한다.

셀 범위는 각 축에서 `minCell = floor(worldMin) - 1`, `maxExclusive = ceil(worldMax) + 1`로 잡고 `[minCell, maxExclusive)`를 순회한다. 음수에도 같은 규칙을 쓴다. 예를 들어 X 경계가 `[-20.2, 20.3]`이면 기본 범위 `-21..20`을 `-22..21`로, `[-20, 20]`이면 기본 범위 `-20..19`를 `-21..20`으로 넓힌다. 경계와 선 하나만 맞닿는 셀은 기본 범위에 넣지 않고, 확장한 바깥 한 줄에 포함한다.

셀 수 `width × height`의 곱은 오버플로와 과도한 할당을 검사한다. 0/음수 크기, 비유한 경계값, 지원하지 않는 Grid/Bounds 변환은 명시적 실패다. 시제품에는 안전한 최대 셀 수 상한을 코드 상수로 둔다.

## 3. 책임과 수정 파일

| 파일 | 구현할 책임 |
|---|---|
| `Assets/Scripts/Stage/Map/PerlinStageGenerator.cs` (신규) | `WorldBounds2D` 경계, 가로·세로 스케일, 밀도, 시드, 단일 암반 타일 참조를 사용해 단일 펄린 노이즈 배열 생성. `SessionManager.Awake`보다 먼저 동기 실행. |
| `Assets/Scripts/Stage/Map/StageMap.cs` | 주어진 셀 직사각형을 단일 충돌 Tilemap에 일괄 적용. 기존 타일 및 `_miningHitPoints` 제거, `SetTilesBlock`, AutoTile/콜라이더 갱신. 채굴 파괴 이벤트를 발생시키지 않음. |
| `Assets/Scenes/Stage_a_1.unity`, `Assets/Scenes/Templates/EmptyStageTemplate.unity` | 기존에 그려진 타일 제거, 생성기 컴포넌트에 해당 씬의 경계와 기존 돌 타일 연결. |

생성기는 씬 컴포넌트의 직렬화 값으로 설정한다. 별도 프로필 자산은 여러 스테이지에서 설정 재사용이 필요해질 때 고려한다. 템플릿의 `StageDefinition` 미할당 문제는 이번 생성기의 지형 생성과 별개로 남는다.

## 4. 초기화 순서

`PerlinStageGenerator.Awake`의 실행 순서를 `SessionManager.Awake`보다 앞에 둔다. 참조·설정 검증 → 셀 범위 계산 → 노이즈 배열 생성 → `StageMap` 일괄 적용 → 타일/콜라이더 갱신 순서다. 정상 설정에서는 생성하면 끝이며, 지형 형태에 따른 성공/실패 판정이나 재생성은 없다. 잘못된 참조·설정은 오류로 기록한다. `StagePopulationManager`의 기존 동작은 이번 단계에서 변경하지 않는다.

`SceneTransitionManager`는 이번 동기식 생성 단계에서 변경하지 않는다. 대형 맵에서 프레임 분할/비동기 생성으로 바꾸면 화면 공개를 준비 신호에 연결한다.

## 5. 구현 순서와 완료 기준

1. 좌표 범위 계산과 설정 검증을 구현한다. 정수/소수/음수 경계에서 예상 셀 수와 끝 좌표를 확인한다.
2. 순수 단일 펄린 마스크 생성과 시드 재현을 구현한다. 동일 범위·설정·시드 결과가 같고, 밀도 `0`은 전부 빈 셀, `1`은 전부 암반인지 확인한다.
3. `StageMap` 일괄 적용을 구현한다. 이전 타일과 채굴 HP가 남지 않으며, 암반의 AutoTile 모양과 CompositeCollider가 준비되는지 확인한다.
4. 두 씬의 빈 Tilemap에 생성기를 연결한다. `Stage_a_1` 로딩에서 첫 물리 스텝 전 지형이 적용되는지 확인한다.
5. 고정 시드로 생성 결과를 재현하고, X/Y 스케일과 밀도 변경이 기대한 방향으로 지형에 반영되는지 확인한다. 비정수 경계가 포함하는 셀 범위를 확인한다.

이 단계의 합격은 **빈 타일맵에 기본 노이즈 지형 생성**이다. 시작 공간, 주 경로 연결, 귀환 가능성, 생물 배치 안전성, 탐사 시간은 합격 조건이 아니다. 노이즈 결과의 고립 공동은 그대로 두고 2차 동굴 편집/연결 보정 단계에서 다룬다.
