# 스테이지 동적 생성기 논의 초안

작성: 2026-09-25. 상태: 추가 논의 필요. 구현 착수용 확정 명세가 아니다.

## 1. 목적과 확정 범위

사용자는 행성의 여러 환경에서 탐사하도록 플레이 구조를 변경하며, 스테이지 로딩마다 몇 가지 파라미터로 타일맵을 생성하는 기능을 원한다. 타일을 독립적으로 무작위 배치하는 방식이 아니라 자연스러운 지형이 필요하다. 먼저 일반적인 방법론을 검토하고 추가 논의를 통해 방식을 확정한다.

현재 확정된 것은 동적 생성의 목표뿐이다. 아래 혼합 알고리즘, 클래스명, 파라미터, 배치 정책은 제안이며 승인된 구현 명세로 취급하지 않는다. 이 문서만 근거로 생성기·새 타일·새 자원·저장 기능을 구현하지 않는다.

이동 선행 계획: [스테이지 중력 및 이동 전환](2026-09-25-session-gravity-movement-plan.md). 이동 계획의 무제한 상승은 첫 구현 기본값이며, 생성기 논의에서 제트팩 제한을 바꾸면 도달 가능성 기준도 다시 정해야 한다.

## 2. 이미지에서 참고할 형태

대화에서 제공된 두 스크린샷은 다음 특징을 보여 준다.

- 큰 공동과 좁은 통로가 연결됨.
- 암반 두께가 일정하지 않고 계단형 윤곽과 오목한 공간이 섞임.
- 벽 내부에 덩어리 형태의 광맥이 있음.
- 자연 지형과 일부 인공 구조물이 함께 나타남.

이미지의 UI 문구와 게임 규칙은 이번 요구 사항이 아니다. 원본 게임의 실제 생성 알고리즘을 이미지로 확인한 것도 아니다. 프로젝트에 영구 저장되지 않은 임시 첨부 경로에 의존하지 않도록 관찰 내용을 이 문서에 남긴다. 이미지와 동일한 아트·구조물·게임 시스템 제작은 확정 범위가 아니다.

## 3. 방법론 비교

| 방법 | 원리 | 유용한 점 | 별도로 해결할 점 |
|---|---|---|---|
| 노이즈 임계값 | 연속 값의 분포를 기준으로 빈 공간/암반 분류 | 자연스러운 덩어리, 지층·광맥·윤곽 변형 | 필수 경로와 공동 연결을 보장하지 않음 |
| 셀룰러 오토마타(CA) | 주변 벽 수에 따라 채움/비움을 여러 번 반복 | 빠르게 동굴 윤곽 생성 | 고립된 공동, 막힌 통로, 목표 규모 제어 |
| 랜덤 워크/굴착 에이전트 | 이동하는 점 주변을 굴착 | 연결된 굴 생성, 분기 제어 | 방향·범위·폭을 제한하지 않으면 단조롭거나 과도하게 비워짐 |
| 방·통로 그래프 | 공간 노드와 연결 관계를 정한 뒤 지형화 | 큰 공간, 필수 경로, 우회로를 의도적으로 배치 | 자연스러운 윤곽을 별도로 생성해야 함 |
| BSP | 공간을 재귀 분할하고 방과 연결을 배치 | 겹침 방지, 구조 제어 | 자연 동굴보다는 정돈된 구조가 나오기 쉬움 |
| 제작된 방/청크 조합 | 연결 조건에 맞춰 수작업 공간을 조합 | 플레이 품질과 특별 공간 통제 | 제작 비용, 반복감, 조각 사이 연결 |
| WFC | 예시 패턴/인접 제약을 만족하는 배치 생성 | 국소 패턴과 구조물 형태 재현 | 전체 이동 경로 보장은 별도, 모순·재시도 처리 필요 |

참고 자료:

- [PCG 교재 저자 공개 장: Constructive Generation Methods for Dungeons and Levels](https://antoniosliapis.com/articles/pcgbook_dungeons.php): 공간 분할, 굴착 에이전트, CA, 플랫폼 생성 및 방 조합 비교.
- [WaveFunctionCollapse 원본 구현](https://github.com/mxgmn/WaveFunctionCollapse): 패턴 제약과 생성 실패 가능성 설명.

위 자료는 방법론 근거이며 Astrodiver에 대한 아래 추천은 프로젝트 요구에 따른 설계 제안이다. 2026-09-24 대화에서 조사한 자료를 정리했으며 패키지 도입을 결정한 것은 아니다.

## 4. 우선 검토할 추천안

**방·통로 그래프 + 굴착 + 노이즈 윤곽 변형**, 필요하면 제한적인 CA 평활화를 조합한다. 모든 기법을 처음부터 넣기보다 그래프/굴착만으로 원하는 형태가 나오는지 먼저 비교한다.

제안 파이프라인:

1. 시드와 맵 크기 결정.
2. 전체 암반 채움, 입장·귀환 공간 예약.
3. 크기가 다른 공동 배치.
4. 주 경로, 분기, 순환 경로를 그래프로 연결.
5. 공동과 폭이 있는 통로 굴착.
6. 윤곽 노이즈 및 선택적 평활화.
7. 좁은 틈/고립 공간 검사, 보호된 경로 복구.
8. 암반 재질과 광맥 배치.
9. 플레이어 크기를 고려한 이동 가능성 및 배치 위치 검증.
10. 타일맵 일괄 적용, AutoTile/충돌 갱신 후 플레이어와 생물 배치.

지형을 자연스럽게 만드는 처리와 이동 경로 보장을 분리한다. 후처리로 필수 통로가 막히는 것을 방지하기 위해 보호 마스크 또는 마지막 복구 단계가 필요하다.

다음 두 연결은 구분한다.

- 이동 연결: 채굴 없이 몸이 통과할 수 있는 공간. 입장과 필수 동선에 적용할 후보.
- 채굴 연결: 암반을 파야 도달하는 자원/선택 공간. 전부 열린 통로로 바꾸면 채굴의 역할이 줄어든다.

단순 flood fill은 빈 셀의 연결만 확인한다. 플레이어 폭·높이, 대각선 틈, 착지 공간, 상승 제한을 고려한 검증이 따로 필요하다. 연료가 무제한이면 높이 제한보다 공간 폭과 연결이 중요하고, 연료가 제한되면 착지점과 왕복 가능성까지 검증해야 한다.

## 5. 기존 프로젝트와 연결되는 수정 범위

2026-09-24~25 소스 확인 기준이다. 구현 시 최신 상태를 다시 확인한다.

| 현재 파일/시스템 | 이후 필요한 검토 |
|---|---|
| `Assets/Scripts/Stage/StageDefinition.cs` | 생성 프로필 참조 추가 후보. 중력 계획과 중복 변경 조정 |
| `Assets/Scripts/Stage/Map/StageMap.cs` | 기존 단일 충돌 Tilemap 유지. 생성 결과 일괄 적용 API, 이전 셀 HP 제거, AutoTile·콜라이더 갱신 |
| `Assets/Scripts/Core/ExploreSession/SessionManager.cs` | 현재 Awake에서 플레이어 생성. 지형 준비 전 물리/입력·세션 시작 방지 |
| `Assets/Scripts/Core/SceneManagement/SceneTransitionManager.cs` | 현재 씬 로드 후 한 프레임 뒤 화면 공개. 명시적인 준비 완료 대기 필요 |
| `Assets/Scripts/Stage/StagePopulationManager.cs` | 현재 Start 자동 생성 및 사각형 안 무작위 배치. 초기 배치/리스폰 모두 벽 중첩 방지 |
| `Assets/Scripts/Stage/StageSpawnAreaCollection.cs` | 생성 결과 후보 위치와 기존 씬 영역의 관계 결정 |
| `Assets/Scripts/World/WorldBounds2D.cs` | 생성 크기로 경계 설정, 플레이어 제한·카메라 영역 일치 확인 |
| `Assets/Scenes/Stage_a_1.unity` 및 `Templates/EmptyStageTemplate.unity` | 정적 테스트 맵 유지 방식과 생성 활성화 방식 결정 |
| `Assets/Scripts/Editor/StageTemplateSceneUtility.cs` 및 StageMap 편집 도구 | 새 설정 생성/미리보기 연결 여부 검토 |

권장 책임 분리(명칭 미확정):

- `StageGenerationProfile`: 크기, 공동/통로, 윤곽, 타일 분포 설정.
- 순수 데이터 생성기: 시드와 설정을 받아 셀 데이터·입장 위치·후보 위치를 출력. Unity 씬 오브젝트 직접 생성과 분리.
- 검증기: 이동 연결·배치 안전성·제약 검사, 실패 사유 반환.
- 초기화 담당: 생성 → 검증 → 타일 적용/충돌 준비 → 경계/입장 위치 → 중력 적용 → 생물/플레이어 활성화 → 세션 시작/화면 공개.
- `StageMap`: 셀과 채굴 상태 관리. 생성 알고리즘을 내부에 한꺼번에 넣지 않음.
- `MiningFragmentDrops`: 기존 파괴 이벤트 구독 및 드롭 배율 적용. 생성기가 직접 자원을 지급하지 않음.

씬 초기화가 기존 PlayerContext/인벤토리/튜토리얼/배터리의 Awake·Start에 미치는 영향도 조사해야 한다. 무조건 플레이어 생성을 뒤로 옮기는 것과 기존 생성 후 비활성 상태로 준비하는 것 중 어느 쪽이 안전한지는 아직 결정하지 않았다.

## 6. 파라미터 후보

| 묶음 | 후보 |
|---|---|
| 맵 규모 | 셀 너비/높이, 좌표 원점, 외곽 두께 |
| 공동 | 개수, 최소/최대 크기, 간격, 수평·수직 분포 |
| 통로 | 최소 폭, 분기 수, 순환 경로 비율, 주 방향 |
| 윤곽 | 노이즈 스케일/강도, 평활화 횟수 |
| 타일 | 기존 MiningTileDefinition 참조, 지층/광맥 분포 규칙 |
| 시드 | 입장별 새 시드, 디버그 고정 시드, 생성기 버전 |
| 안전성 | 입장 여유 공간, 최소 통과 폭, 검증/재시도 상한 |

처음부터 모든 내부 변수를 Inspector에 노출하지 않는다. 맵 크기, 공동 크기, 통로 폭 등 결과를 예측하기 쉬운 설정부터 제공하고 나머지는 프로토타입으로 필요성을 확인한다.

## 7. 추가 논의로 확정할 사항

| 질문 | 현재 추천 또는 선택지 | 결정이 미치는 영향 |
|---|---|---|
| 탐사의 주 방향은? | 넓게 퍼진 동굴 / 지표에서 하강 / 횡방향 진행. 현재는 동굴형 추천 | 그래프 배치와 경로 방향 |
| 맵 크기·탐사 시간은? | 미정. 대표 크기와 목표 플레이 시간을 먼저 정함 | 생성 비용, 공간 밀도, 자원량 |
| 제트팩 사용 제한은? | 첫 이동 구현은 무제한 추천. 연료/과열은 별도 결정 | 도달/왕복 가능성, 착지점 간격 |
| 입장·귀환은? | 고정 우주선 주변 공간 예약 / 생성 위치로 이동 / 별도 귀환 지점 | 예약 공간과 필수 연결 |
| 얼마만큼 채굴해야 이동하는가? | 주 경로 개방 + 선택 광맥 매립을 우선 검토 | 초기 공극률, 자원 소비, 접근 검증 |
| 모든 공동을 연결할 것인가? | 필수 공간만 보장하고 선택 공간은 매립 가능 | 고립 공간 보정 정책 |
| 외곽은 파괴 가능한가? | 미정. 기존 월드 경계와 타일 정책을 함께 논의 | 탈출 방지, 새 정의 필요 여부 |
| 생물 배치는? | 기존 생물 행동 유지, 생성된 빈 공간에서 안전 배치 추천 | 배치 후보, 리스폰, 이동 범위 |
| 재시도도 새 맵인가? | 매 로딩 새 생성 요청은 있으나 실패 재도전 시드 정책은 별도 확정 | 재현성 및 플레이 경험 |
| 저장/재방문은? | 첫 버전은 영구 지형 저장 제외 추천 | 시드·파괴 셀 저장과 버전 호환 |
| 특별 공간은? | 수작업 방/구조물 삽입은 추후 후보 | 템플릿과 연결 규칙 |
| 배경/장식도 생성하는가? | 첫 버전은 충돌/채굴 타일맵 우선 추천 | 시각 작업 범위와 성능 |

새 환경 아트·자원 종류·광맥 경제 밸런스는 자동 포함하지 않는다. 기존 타일 정의로 기술 시제품을 만들지 여부부터 결정한다.

## 8. 확정 후 예상 단계

1. 이동 조작과 위 핵심 질문 확정.
2. 동일 크기/시드 집합으로 2~3개 생성 후보를 셀 미리보기로 비교. 아직 세션 전체와 연결하지 않음.
3. 형태와 연결 검증 결과를 보고 알고리즘·파라미터 확정.
4. 타일맵 적용과 로딩 준비 신호 통합.
5. 자원 분포와 안전한 생물 배치 통합.
6. 다수 시드 검증, 성능 측정, 실제 탐사로 조정.

시제품 합격 기준도 알고리즘 확정 시 수치화한다. 후보 검증 항목은 동일 시드/설정/생성기 버전에서 동일 결과, 안전한 입장, 필수 경로 통과, 유효한 광맥, 중복/벽 내부 생물 배치 방지, 유한한 재시도, 로딩 시간/메모리, 채굴·드롭 회귀다.

난수는 지형/광맥/생물 배치별로 분리할 것을 추천한다. 생물 수만 바꿨는데 지형까지 달라지는 일을 막는다. 실패 시 무한 재시도하지 않으며, 검증된 대체 맵과 진입 실패 처리 중 어떤 정책을 쓸지 정해야 한다.

## 11. 2026-09-27 결정안 초안: 노이즈 기반 지형과 1차 시제품

### 11.1 이동 전환에서 반영할 사실

- SessionPlayer는 좌우 이동과 지속 상승을 사용하며 상승 연료/횟수 제한은 없다. 상승 키를 놓으면 중력으로 감속·낙하한다.
- 중력은 스테이지 정의에서 적용되고, 추진 중에도 유지된다. 중력이 강하면 상승 가속과 최고 상승 속도 도달 양상이 달라지도록 구현했다.
- 기본 중력 1.0, 상승 속도 4, 상승 가속도 30, 최대 낙하 속도 12는 현재 구현 기본값이다. 이 값들이 목표 지형 크기·이동 시간에 맞는지는 아직 검증되지 않았다.
- 따라서 지형은 연료 소비나 단방향 낙하를 전제로 설계하지 않는다. 무제한 상승은 수직 이동 제약을 완화하지만 좁은 암반 통로를 통과 가능하게 만들지는 않으므로, 탐사감을 위해 열린 동선과 채굴 동선을 별도로 다룬다.
- 2026-09-27 현재 동작 이력은 구현 기록이지 검증된 조작감 결과가 아니다. 탐사 시간과 수직 맵 규모 확정 전에 수동 플레이 검증이 필요하다.

### 11.2 생성 방식 제안

기본 지형은 **노이즈 필드의 임계값 분류**로 만든다. 각 셀에서 저주파 노이즈를 중심으로 암반/공간을 판정하고, 필요하면 서로 다른 스케일의 저·중주파 신호를 가중 조합해 큰 지형 덩어리와 불규칙 윤곽을 만든다. 독립 셀 난수로 타일을 흩뿌리지 않는다. 정확한 노이즈 함수/옥타브 수/임계값은 시제품 비교 전까지 고정하지 않는다.

후속 동굴 요소는 원본 필드를 대체하지 않는 **선택적 2차 편집 단계**로 둔다. 예를 들어 필수 접근 통로를 넓히거나, 작은 공동/굴착 분기를 더하거나, 아주 제한적으로 평활화할 수 있다. 각 편집 단계는 켜고 끌 수 있고 같은 시드의 원본 결과와 편집 결과를 나란히 비교할 수 있어야 한다. 1차 시제품에서는 동굴 후처리의 유무/효과를 비교 대상으로 남기며, 그래프·WFC·CA를 기본 생성기로 채택하지 않는다.

노이즈만으로 입장 지점과 연결성이 보장되지는 않는다. 입장·귀환 예정 지점 주변은 예약된 안전 공간으로 확보하고, 검증에서 막히면 제한된 보정(필요한 연결부만 최소 굴착/확장)을 적용하는 방식이 후보이다. 이 보정이 자연스러운 원본 지형을 크게 바꾸지 않도록 수정 셀 수/범위를 제한하고, 한계를 넘으면 실패로 판정한다. 통로 폭, 허용 수정량, 실패 처리 방식은 시제품 결과로 결정한다. 무한 재시도는 하지 않는다.

광맥은 지형 노이즈와 난수 흐름을 분리한다. 1차 형태 비교에서는 자원 분포를 꺼서 윤곽을 먼저 평가하고, 타일맵 연결 시점에는 새 타일/경제 밸런스 없이 기존 MiningTileDefinition으로 소량의 광맥 배치가 가능한지만 별도 기술 확인한다. 생성기는 드롭을 지급하지 않고 기존 채굴·파괴 이벤트 소유권을 유지한다.

### 11.3 1차 시제품 범위

**목표:** 전체 세션이나 씬 로딩과 붙이기 전에, 노이즈 베이스가 자연스럽고 플레이 가능한 기본 지형을 만드는지 여러 시드와 설정으로 판단한다.

포함 후보:

1. 순수 셀 데이터 생성 및 시드 고정 재현.
2. 동일한 맵 크기/입구 조건에서 노이즈 설정 2~3종 비교. 각 설정은 같은 시드 목록으로 미리보기한다.
3. 편집 없음과 제한적인 동굴 후처리를 비교할 수 있는 단계 분리.
4. 셀 미리보기와 최소한의 수치 요약(공간 비율, 가장 큰 빈 공간, 빈 공간 연결 성분 수, 입구에서 닿는 영역, 보정에 사용된 셀 수).
5. 입장 안전 공간과 플레이어 몸체 크기를 고려한 통과 가능성 검사. 단순 셀 flood fill만으로 통과 성공을 판정하지 않는다.
6. 재현 가능한 실패 보고와 유한한 생성/보정 종료. 대체 맵/진입 거부 중 무엇을 할지는 별도 결정.

제외:

- SessionManager/SceneTransitionManager 초기화 순서, 타일맵 적용, AutoTile/Collider 준비 완료 신호 연동.
- StagePopulationManager 생물 스폰/리스폰 및 광맥 경제 밸런스.
- 새 환경 아트, 장식/배경 생성, 특별 수작업 방/구조물, 저장·재방문 지형 복원.
- 제트팩 연료·과열·횟수 제한, 지형 기반 업그레이드, 신규 게임 규칙.

### 11.4 1차 시제품의 판단 기준 초안

- 같은 생성기 버전·설정·시드는 동일한 셀 결과를 만든다.
- 예약된 입장 공간이 안전하고, 기준 플레이어가 의도한 시작 공간에서 움직일 수 있다.
- 지도 대부분이 무작위 점무늬가 아닌 연결된 자연스러운 암반 덩어리와 공간 윤곽을 보인다. 이 항목은 셀 미리보기 검토로 판정한다.
- 입구에서 핵심 탐사 영역까지 이동 연결이 보장되는지, 그리고 선택 영역 중 채굴이 필요한 곳이 남는지 수치와 미리보기로 구분된다.
- 후처리/보정은 원본을 추적 가능하게 하고, 수정량 상한을 넘으면 빠르게 실패한다.
- 2~3개 설정의 동일 시드 결과를 비교해 노이즈 설정과 후처리가 각각 형태·연결성에 미치는 영향을 설명할 수 있다.

수치 목표(맵 셀 크기, 공간 비율, 최소 통로 폭, 연결 영역 비율, 생성 시간)는 대표 맵 크기와 목표 탐사 시간, 실제 SessionPlayer 조작감 확인 후 정한다. 이동 파라미터가 구현됐다는 사실만으로 이 목표들을 임의 설정하지 않는다.

### 11.5 §7 질문의 잠정 응답

| 질문 | 잠정 답변 | 남은 결정 |
|---|---|---|
| 탐사의 주 방향은? | 우선 넓게 퍼지는 동굴형. 수직 확장도 허용하되 하강만 강제하지 않는다. | 수평 대 수직 비율과 귀환 지점 위치 |
| 맵 크기·탐사 시간은? | 시제품 비교를 위해 임시 대표 크기 하나를 선택하되, 이를 최종 값으로 취급하지 않는다. | 셀 크기와 목표 플레이 시간 |
| 제트팩 사용 제한은? | 구현된 무제한 지속 상승을 기준으로 검토하고 연료/과열을 전제하지 않는다. | 플레이 감각 검증 뒤에도 무제한 정책을 유지할지 |
| 입장·귀환은? | 시작 지점은 반드시 안전 공간으로 예약한다. 귀환은 같은 지점으로 돌아오는 안을 우선 검토한다. | 고정 우주선/생성 위치/별도 출구 중 결정 |
| 얼마만큼 채굴해야 이동하는가? | 핵심 동선 일부는 열린 이동 경로, 자원/선택 공간은 암반 뒤에 둘 수 있게 분리한다. | 필수 동선과 선택 채굴 비율 |
| 모든 공동을 연결할 것인가? | 시작 공간과 핵심 탐사 영역은 연결 보장, 선택 공간은 고립 가능성을 허용하되 의도 여부를 지표로 기록한다. | 고립 공간의 허용 비율과 채굴 연결 요건 |
| 외곽은 파괴 가능한가? | 시제품에서는 경계 바깥으로 탈출하지 않는 닫힌 외곽으로 취급한다. | 기존 타일의 채굴 가능 여부와 월드 경계 정책 |
| 생물 배치는? | 생성 전용 시제품 범위 밖. 이후 빈 공간/안전 조건으로 배치한다. | 기존 행동 반경과 리스폰 위치 계약 |
| 재시도도 새 맵인가? | 동일 입력은 디버그 재현 가능해야 한다. 플레이 재시도에서 새 시드를 쓸지는 미정. | 실패·재도전 시드 수명 |
| 저장/재방문은? | 영구 지형 저장은 첫 버전에서 제외하는 안을 유지한다. | 시드만 저장할 필요 여부 |
| 특별 공간은? | 1차 시제품 제외. 필요 시 노이즈 맵 이후 별도 삽입 시스템으로 논의한다. | 연결 규칙/콘텐츠 제작 방식 |
| 배경/장식도 생성하는가? | 충돌/채굴 지형 미리보기만 다룬다. | 후속 시각 레이어 범위 |

이 표는 사용자 승인 전에 확정 요구사항으로 승격하지 않는다. 우선 사용자가 제시한 노이즈 기반 베이스와 2차 후처리 원칙만 방향 제안으로 기록한다.
